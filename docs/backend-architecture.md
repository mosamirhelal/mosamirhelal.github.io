# Al-Khateeb Backend Architecture

> Backend source code is not published in this repository. Both Google Apps Script deployments are private web apps.

---

## System Overview

The Al-Khateeb school system runs on two independent Google Apps Script backends, each backed by a separate Google Sheets database.

```
Backend A  →  Grades DB     →  /alkhateeb-students, /alkhateeb-results, /alkhateeb-degrees
Backend B  →  HR DB         →  /alkhateeb-hr
```

---

## Backend A — Grades & Results

Powers the Student Results Portal and the Teacher Grades Portal.

### Database Schema

On first run, `setupDatabase()` provisions the entire database from scratch: grade sheets for each academic level (3rd–6th Primary, 1st–2nd Preparatory), a users sheet, a movement audit log, and a system settings sheet. Column headers are auto-generated by combining month × exam type × subject. The settings sheet uses dropdown validations to control month filter, exam type, results visibility, and completion status.

### Arabic Text Normalization

All name searches pass through `normalizeArabic()` before matching:

- Hamza variants (`أ إ آ`) → unified as `ا`
- Taa marbouta (`ة`) → `ه`
- Alef maqsura (`ى`) → `ي`
- All diacritics (tashkeel) → stripped

A parent searching for `محمد` will correctly match `مُحَمَّد`.

### Authentication

Login is rate-limited with a temporary account lockout after repeated failures. On valid credentials, a time-limited session token is issued and stored in `ScriptProperties`. Accounts with a non-active status are rejected regardless of credentials. All auth events are written to the audit log.

### Subject-Level Authorization

Every protected API call verifies that the authenticated teacher's `allowedSubjects` field covers the requested subject. Unauthorized attempts are logged with the teacher's name and the subject they tried to access.

### Grade Saving

1. Input validation: every score must be empty, `غ` (Absent), or a number between 0–100.
2. Write-locking via `LockService` prevents concurrent edit conflicts.
3. Change detection: the backend reads the current column and writes back only values that actually changed.
4. Modified values are written as a single range operation (`setValues`), not cell-by-cell.
5. The lock is released in a `finally` block.

### Student Results Lookup

**By ID:** checks global visibility flag → reads per-subject maximums → applies month/exam-type filters from settings → calculates total, maximum, and percentage.

**By Name:** normalized through `normalizeArabic()` first. Result count is limited to prevent data enumeration; a query returning too many matches asks the user to narrow the search.

### Token Cleanup

A time-based trigger runs on a periodic schedule, scanning `ScriptProperties` for expired token keys and deleting them.

## Backend B — HR & Attendance

Powers the Staff HR Portal.

### Authentication

Dual-role system: Admin and Teacher. After login, the `role` field in the response determines which dashboard the frontend shows. Tokens are time-limited and stored in `sessionStorage` (invalidated on tab close). The teacher list is cached client-side to avoid re-fetching on navigation.

### Date Normalization

`forceStringDate()` handles the timezone offset that Google Apps Script applies to JavaScript `Date` objects before formatting. String dates in `dd/mm/yyyy` are converted to `yyyy-mm-dd` for consistent ISO sorting.

### Attendance Recording

Accepts an array of records in a single API call (used when the admin applies an operation across multiple days or multiple teachers). The national ID is looked up server-side from the teacher code and is never sent from the frontend.

### Record Editing

Finding the correct row without an exposed row ID uses server-side field matching across a combination of record attributes. Date and admin fields are immutable; only type, amount, and notes can be updated.

### Aggregated Reports

`setupAggregatedReports()` builds a live formula sheet once at setup time. For each teacher, it inserts rows with dynamic `SUMIFS` formulas covering all operation types. New records update all aggregated totals instantly through Google Sheets' formula engine — no backend recalculation needed at query time.

## Security Comparison

| Feature                         | Backend A (Grades)                    | Backend B (HR)                        |
| ------------------------------- | ------------------------------------- | ------------------------------------- |
| **Auth Method**                 | Token via UUID                        | Token via UUID                        |
| **Token Expiry**                | Time-limited session                  | Time-limited session                  |
| **Client Storage**              | `localStorage`                        | `sessionStorage`                      |
| **Brute Force Guard**           | ✅ Rate-limited with temporary lockout | ❌ N/A                                |
| **Role System**                 | Subject-level per teacher             | Admin / Teacher roles                 |
| **Concurrent Write Protection** | ✅ Write-locking (LockService)        | ❌ N/A                                |
| **Unauthorized Access Logging** | ✅ Full audit trail                   | ✅ Full audit trail                   |
| **Results Visibility Control**  | ✅ Remote on/off via settings sheet   | ❌ N/A                                |
| **Token Auto-Cleanup**          | ✅ Periodic scheduled trigger         | ✅ On every request                   |
| **GET Request Blocking**        | Partial (public results via GET)      | ✅ Full block — returns 403           |
| **XSS Prevention**              | ✅ `escapeHTML()` on all user content | ✅ `escapeHTML()` on all user content |
| **Source Code Published**       | ❌ Private                            | ❌ Private                            |
